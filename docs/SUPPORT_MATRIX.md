# URP — Supported Runtime and Database Matrix

**Baseline date:** 2026-11-11  
**Policy:** only combinations marked *primary* are release-blocking CI targets. Other combinations are compatibility targets only after the corresponding matrix job exists.

## Runtime matrix

| Component | Primary | Compatibility / policy |
|---|---|---|
| Rust toolchain | 1.99.1 stable | Exact toolchain pinned in `rust-toolchain.toml`; update through a reviewed PR and full CI. Nightly is not supported for production. |
| Node.js | 26.x Active LTS | 24.x Maintenance LTS may be added as a compatibility CI lane. Do not use odd/experimental or alpha lines in production. |
| Package manager | pnpm 10.34.9 | Exact version recorded in root `package.json` `packageManager`; lockfile changes are reviewed. |
| Next.js | 16.2.x App Router | Pin exact patch in lockfile. Do not float major versions. |
| React | 19.2.x | Resolved version follows the supported Next.js release. |
| TypeScript | 5.9.x | Strict mode enabled. |
| Rust HTTP runtime | Tokio + Axum | Exact dependency graph is recorded in Cargo.lock once generated by the Rust toolchain. |

Node.js 26 entered Active LTS on 2026-10-28. Production must use an Active LTS or Maintenance LTS line; Node 27 is Alpha and is excluded. See the [Node.js release schedule](https://github.com/nodejs/Release#release-schedule) and [official release status](https://nodejs.org/en/about/previous-releases).

Next.js 16.2 is the selected App Router baseline. The documented minimum Node.js version is lower than our deployment baseline; URP intentionally selects the current Active LTS line instead of targeting the minimum. See [Next.js 16.2](https://nextjs.org/blog/next-16-2) and [installation requirements](https://nextjs.org/docs/app/getting-started/installation).

## Database matrix

| Database | Status | URP deployment contract |
|---|---|---|
| PostgreSQL 18 | **Primary production target** | Required for multi-user, multi-node, high-write, HA and production workloads. |
| PostgreSQL 17 | Compatibility target | Must pass the same persistence and migration contract tests before release support is claimed. |
| SQLite 3.54.1 | **Supported single-host target** | Embedded/local/small single-host deployment only. P02 adds CI adapter and migration tests before release support is claimed. |
| PostgreSQL 19 | Not supported yet | Release candidate as of the baseline date; do not use as production baseline until GA and URP conformance validation. |

PostgreSQL 18 and 17 are supported upstream release lines. PostgreSQL 19 GA is scheduled for 2026-11-19; on this baseline date it is still a release candidate. See the [PostgreSQL versioning policy](https://www.postgresql.org/support/versioning/) and [PostgreSQL 19 RC announcement](https://www.postgresql.org/about/news/postgresql-19-rc-1-released-3409/).

SQLite 3.54.1 is the current selected baseline. The release history records 3.54.1 on 2026-10-16. See [SQLite release chronology](https://www.sqlite.org/chronology.html).

### SQLite limitations

- SQLite is supported only on a single application host using local durable storage.
- Do not place the database, WAL, or SHM files on a shared network filesystem.
- Do not share one SQLite database between multiple application nodes.
- PostgreSQL is mandatory for HA, multi-node deployment, and sustained concurrent writes.
- Backend-specific capability differences must return explicit errors; never silently pretend all PostgreSQL behavior is available.

| Linux aarch64/arm64 | Compatibility target; release support requires CI build and runtime test |

## Browser baseline

Use the current stable release of Chrome, Edge, Firefox and Safari. The Next.js App Router documented baseline is Chrome/Edge 111+, Firefox 111+ and Safari 16.4+. URP UI acceptance tests must include Chromium-based E2E coverage plus keyboard/accessibility tests. See [Next.js supported browsers](https://nextjs.org/docs/app/getting-started/installation).

## Update policy

1. Security fixes are assessed immediately; critical fixes may trigger an out-of-cycle update.
2. Review Rust, Node.js, Next.js, PostgreSQL, SQLite and package-manager updates at least monthly.
3. Pin exact runtime/tool versions and commit lockfiles for deployable applications.
4. Upgrade one major runtime/database line at a time with CI and migration evidence.
5. Do not mark a compatibility target supported until its tests are green and its behavior is documented.
6. Record exceptions with owner, rationale, expiry and affected release.

## Initial CI lanes

- Required: Rust 1.99.1 on Linux x86_64.
- Required: Node.js 26.x + pnpm 10.34.9 + Next.js 16.2.x.
- Assigned release-blocking persistence lane: PostgreSQL 18 and SQLite 3.54.1 (activated with P02 storage integration).
- Follow-up compatibility lane: PostgreSQL 17 and Node.js 24.x.
- Arm64 CI is follow-up work, not an assumed support claim.
